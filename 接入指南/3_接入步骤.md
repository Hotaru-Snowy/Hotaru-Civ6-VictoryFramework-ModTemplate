> 基础步骤（三步接入、字段表、两个高频坑）在 `../README.md` 的**第三章**。
> 这里只讲三件那边没细说的：迁移对照 / 校验清单 / 与覆写官方 UI 文件的 MOD 共存。

## 一、迁移：你原来已经有一份 WorldRankings 替换脚本

常见写法是：用 `ReplaceUIScript` 抢 WorldRankings 槽，脚本里 `include("WorldRankings_Expansion2")`，
再重定义 `PopulateTabs`、包装 `PopulateGenericInstance`。接入框架就是把它拆成"数据 + 一个 Provider"：

| 你原来的东西 | 接入后怎么处理 |
|---|---|
| 那条 `ReplaceUIScript` | **删掉**（框架独占该槽位） |
| 重定义的 `PopulateTabs` | **整段删掉**（官方循环 + 框架分发已覆盖） |
| 包装 `PopulateGenericInstance` / `PopulateGenericHeader` 的代码 | 改写到 Provider 的 `PopulateRow` / `HeaderIcon` |
| 自己写的 `ViewXxx(victoryType)` | 挂到 Provider 的 `View` |
| 自己写的 `g_victoryData[vt] = {...}` | **删掉**，改填 `GetScore` / `GetText` / `Summary` |
| 读玩家属性、拼文本的辅助函数 | 原样搬进 Provider 文件 |

`View` 的骨架照官方 `ViewGeneric` 写：
`ResetState` → `Controls.GenericView:SetHide(false)` → `ChangeActiveHeader` →
`PopulateGenericHeader` → `g_GenericIM:ResetInstances()` / `g_GenericTeamIM:ResetInstances()` →
逐行 `PopulateGenericInstance` → `RealizeGenericStackSize()`。
完整示例见 `1_Provider模板.lua` 的 `View` 字段。

> 如果你原来 `include` 了自己的辅助脚本，继续 `include` 即可 ——
> 但那个文件仍要**同时**出现在工程里并用 ImportFiles 挂载，否则 `include` 找不到。

## 二、校验清单

- [ ] Provider 文件名 = `HotaruVictoryFramework_Provider_` + `VictoryType`，**逐字符一致**
- [ ] InGameActions 里有 ImportFiles，且挂的是这个 Provider 文件
- [ ] 原来的 WorldRankings `ReplaceUIScript` 已删除
- [ ] Dependencies 里已声明框架
- [ ] `Lua.log` 里出现 `[HotaruVictoryFramework] 已登记 Provider: VICTORY_XXX`
- [ ] 世界排名页出现你的页签，点击后内容正确
- [ ] 和另一个也用框架的胜利 MOD 同时启用，两个页签都在

## 三、与「覆写官方 WorldRankings 文件」的 MOD 共存

有一类 MOD 不走 `ReplaceUIScript`，而是用 `ImportFiles` 直接覆写官方的
`WorldRankings_Expansion2.lua` / `WorldRankings.xml`。这类 MOD **不需要任何改动**：

1. 框架接入层的第一行是 `include("WorldRankings_Expansion2")` ——
   载入的就是被覆写后的那一份，对方的自定义函数、`g_victoryData` 条目、XML 控件全部照常存在。
2. 框架**不覆写** `WorldRankings.xml`，不会顶掉别人加进去的控件。
3. 框架**不重写** `PopulateTabs`，只包装 `ViewGeneric` / `IsCustomVictoryType` / `AddTab`，
   对方在 `PopulateTabs` 里做的路由与定制**完整保留**。

> 前提：对方的文件加载顺序在框架之前。它用 `ImportFiles` 覆写官方文件名，
> 与框架的 `ReplaceUIScript` 不在同一个槽位，天然满足。
